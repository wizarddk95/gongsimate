### 평가에서 분리할 것

- Q01과 Q09는 같은 의도 그룹이며 동일한 필수 근거 집합을 사용한다. 표현 차이에 따른 순위 변화를 따로 비교한다.
- Q07은 검색 및 **계산**의 결합 사례다. BM25가 필요한 숫자를 모두 찾아도 계산 정확성은 별도 검증한다.
- Q10은 정답 근거 청크가 없는 경계 사례다. Recall@k의 양성 질문 분모에 넣지 않고, 기간 검증·답변 보류를 평가한다. 관련 없는 검색 결과가 반환되는 것 자체를 BM25 실패로 판정하지 않는다.
- 부분 근거만 회수한 복합 질문은 전체 정답으로 처리하지 않는다. 주장별 근거 회수와 질문 전체 충족을 함께 기록한다.
- `expected`가 원문과 충돌하면 원문 기준으로 `answerable=partial/none`을 기록하고 이유를 남긴다. 질문을 조용히 다른 질문으로 바꾸지 않는다.

### 근거 1건 기록 양식 — 필요한 만큼 복제

```yaml
question_id: Q01
claim_id: Q01-C1                 # 필수 주장/수치마다 하나
answerability: pending           # supported | partial | unsupported | pending
source:
  receipt_no: "20260323000847"
  source_sha256: "ff2ee7ca28c18ac6487ea4349cfde9d8dca4d03771c2a8a1bd37c9d81cfd7bb6"
  zip_member_name: null          # ZIP 안의 정확한 멤버 이름
  zip_member_order: null         # 동명 멤버 대비
  document_title_observed: null  # 원문에 표시된 제목; 내부 role 추정 금지
  section_path_observed: null
  location:
    kind: null                   # paragraph | table
    paragraph_anchor: null       # 짧은 시작 구절 등 원문 재탐색 단서
    table_title: null
    row_label: null
    column_header: null
    unit_cell: null
    raw_locator_hint: null       # 확인 가능한 원문 경로/구조; XML 줄 번호는 보조
  evidence_excerpt: null         # 주장에 필요한 최소 원문; 한 문장/셀 범위
  supports_claim: null           # 어떻게 지지하는지 한 줄
review:
  reviewer: null
  checked_at: null               # ISO 8601 +09:00
  notes: null
```

복수 행·열이나 두 문단이 필요한 경우 `claim_id`를 나누거나 근거 레코드를 여러 개 둔다. 표 수치에는 값 셀뿐 아니라 기간 헤더·연결 여부·단위 셀의 원문 위치를 남긴다. 답변 가능 여부는 필수 주장에 대한 근거를 확인한 뒤 문항 단위로 확정한다. ④단계에서 이 레코드에 `element_id`와 해당 요소가 원문 범위를 보존하는지 여부를 추가한다.

### 실제 ③ 작업 순서

1. S25 원본 ZIP과 파싱 manifest를 대조해 스냅샷을 잠근다.
2. Q01의 제품명과 용도를 별개 주장으로 나누어 원문 멤버·문단/표 범위를 기록한다. Q09는 그 라벨을 참조한다.
3. Q02~Q08을 위 작업표 순서대로 검수한다. 원문에 없는 필수 사실을 발견하면 `unsupported`와 이유를 기록하고 다음 문항으로 간다.
4. Q10은 원문 근거 레코드를 만들지 않고 스냅샷·기간 제약으로 보류 판정을 기록한다.
5. 문항마다 `supported / partial / unsupported`와 필요한 근거가 모두 표시됐는지 확인한 뒤 ④ Element 연결로 넘어간다.

### 청킹·평가 입력으로 넘길 조건

1. `element_id`와 **셀 좌표 및 원문 주장 범위**를 함께 보존한다. 표 전체를 회수해도 표제·기간·단위가 떨어져 나가면 Q05~Q08의 충분한 정답 근거로 세지 않는다.
2. 표의 `TD/TE` 제목 셀은 `header_role=unknown`일 수 있다. 이는 텍스트·좌표가 빠졌다는 뜻이 아니다. `TH/THEAD`에만 `header`를 주는 현재 파서 정책에 따라 헤더 의미를 **행·열 위치와 원문 표 구조로 판정**해야 한다.
3. E227과 E228은 **서로 다른 표 요소**다. E228만으로 원 단위와 사업기간을 답변에 전달하지 못한다. E81과 E82도 연결기준 표시가 문단과 표로 나뉜다.
4. E186의 매출 오기는 검색 결과에 등장할 수 있다. 이를 Q03·Q06·Q07의 정답으로 매핑하지 않고, 잘못된 근거 선택을 진단하는 별도 충돌 사례로 둔다.
5. `source_locator`는 전처리 후 트리의 경로이며 바이트 오프셋이 아니다. 여기서는 고정 원문의 표/문단과 요소 내용·핵심 셀을 대조했다. 파일 전체의 locator 왕복 검사나 모든 셀의 의미 검증을 수행했다는 주장은 하지 않는다.
