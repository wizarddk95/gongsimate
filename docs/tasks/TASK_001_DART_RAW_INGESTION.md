# TASK-001 — DART 공시 원본 한 건 수집

이 문서 전체를 Cursor 작업 컨텍스트로 제공한다. 작업 대상은 사용자가 Cursor에서 연 새 프로젝트 저장소다. 이 문서는 구현 지시서이며 구현·API 호출·테스트가 이미 완료됐다는 뜻은 아니다.

## 목표와 프로젝트 맥락

Python과 uv를 사용하고 GitHub으로 변경 이력을 관리한다. 국내 공시 리서치 에이전트의 첫 구현이다. 제품의 주 사용자는 개인 투자자이며, LLM이 필요에 따라 검색 도구를 선택한다. 월 클라우드 운영비 상한은 50만 원이다.

향후 전체 상장사의 FY2023–2025 정기공시와 정정을 처리하고 다른 공시 유형으로 확대한다. 이번에는 접수번호 하나를 입력받아 원본 ZIP과 추적 메타데이터를 저장하는 CLI만 구현한다. 개발 중 로컬 파일 저장은 허용하며 운영 인프라는 이후 클라우드에 배포한다.

## 진행 방법

1. 현재 저장소의 파일·Git 상태·프로젝트 지침을 확인한다. 기존 작업을 삭제하거나 덮어쓰지 않는다. 새 코드베이스를 전제로 하되 기존 파일이 있으면 충돌을 피한다.
2. 구현할 파일과 책임을 5줄 이내로 알리고 바로 구현한다. 단순한 기술 선택마다 사용자 승인을 요구하지 않는다.
3. 기존 프로젝트 설정이 없다면 Python 3.12와 uv 기반 패키지 프로젝트로 시작한다. 이미 다른 버전이 명시돼 있다면 호환성을 확인하고 존중한다.
4. 새 기능은 feature/dart-raw-ingestion 브랜치에서 작업한다. 사용자의 진행 중 변경을 강제로 이동·reset하지 않는다. Git이 없으면 초기화하되 원격 생성이나 push는 하지 않는다.
5. 외부 통신을 모킹한 테스트와 lint를 실행한다. 실 API 검증은 키와 실제 접수번호가 준비된 경우에만 수행한다. 키가 없어도 구현과 오프라인 검증은 완료한다.
6. 변경 요약·검증 결과·미검증 사항을 보고한다. 커밋 메시지와 PR 설명 초안을 제공하되 이 작업서는 자동 commit/push/merge까지 요구하지 않는다.

## 입력과 실행 계약

목표 실행 인터페이스:

    uv sync --locked
    uv run dart-ingest --receipt-no <14자리_접수번호> --output-dir ./data/raw
    uv run pytest
    uv run ruff check .

첫 의존성 추가 시 uv로 pyproject.toml과 uv.lock을 생성하고 이후 위 locked 설치를 검증한다. HTTP 클라이언트는 httpx, 테스트는 pytest, lint는 ruff를 기본으로 한다. 한 건 처리이므로 동기식으로 구현한다. CLI는 argparse로 충분하다. 불필요한 프레임워크·DI 컨테이너·범용 추상 클래스는 추가하지 않는다.

- 접수번호는 숫자로만 이뤄진 길이 14의 문자열. 검증 전에 HTTP 요청하지 않는다.
- API 키는 OPENDART_API_KEY 환경변수로 받는다. CLI 인자로 받거나 코드에 쓰지 않는다.
- 키가 없으면 안전한 오류와 비정상 종료 코드로 끝낸다. 네트워크 없이 유효한 기존 결과를 재사용하는 경우에는 키가 없어도 된다.
- .env를 사용한다면 로딩 방식을 명시한다. .env 파일이 저절로 로딩된다고 가정하지 않는다. .env.example은 빈 값만 기록한다.
- Windows PowerShell에서 환경변수를 설정하고 실행하는 예를 README에 적는다. 예시 키는 실제 키가 아닌 placeholder여야 한다.

## 공식 API와 응답 처리

공식 명세(2026-09-21 확인):
https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003

- GET https://opendart.fss.or.kr/api/document.xml
- 매개변수: crtfc_key, rcept_no.
- 성공 원본은 ZIP 바이너리다. URL 확장자가 .xml이라고 XML 문서로 저장하지 않는다.
- HTTP 성공 여부와 API 응답 성공 여부를 구분한다. XML status/message 오류 또는 예기치 않은 응답을 원본 ZIP으로 확정 저장하지 않는다.
- ZIP 열기 및 내용 무결성을 검사하되 파일을 추출하지 않는다. 빈 ZIP·손상 ZIP을 거부한다.
- HTTP timeout과 응답 크기 상한을 명시한다. 초기값은 timeout 30초, 압축 응답 50MiB, 검증할 압축 해제 총량 200MiB를 제안한다. 검증 전 ZIP 메타데이터로 제한을 확인하고 제한 초과는 별도 오류로 보고한다. 이 값은 공식 DART 한도가 아니라 프로그램 보호용 설정이다.
- 이번 작업은 자동 재시도 없이 실패 유형을 명확히 반환한다. 배치·backoff·스케줄링은 다음 작업에서 구현한다.
- 요청 URL에 인증키가 있으므로 HTTP 예외를 그대로 출력하지 않는다. 로그·traceback·메타데이터에 인증키/인증키가 포함된 URL이 남지 않도록 안전한 오류로 변환한다.

## 출력과 원본 보존

완료된 결과:

    data/raw/dart/<receipt_no>/document.zip
    data/raw/dart/<receipt_no>/metadata.json

metadata.json 필수 필드:

- schema_version: 1
- source: dart
- receipt_no: 요청 접수번호
- artifact_type: disclosure_original_zip
- source_endpoint: 인증키나 쿼리문자열 없는 API URL
- fetched_at: 실제 취득 UTC 시각(시간대 포함)
- sha256: 저장할 ZIP 원본 바이트의 SHA-256
- size_bytes: ZIP 바이트 수
- original_filename: document.zip

이번 API 응답만으로 확인하지 못하는 회사·사업연도·보고서명·공개시각을 접수번호나 파일명에서 추측해 채우지 않는다. 이 필드는 다음 공시 목록 조회 단계에서 출처와 함께 연결한다. 취득시각은 공시시각이 아니다.

원본 바이트를 변환하거나 ZIP을 재압축하지 않는다. ZIP 본문 파싱·청킹은 이번 범위 밖이다.

## 재실행과 중단 계약

이번 버전은 CLI 단일 실행자 기준이다. 동시 수집 잠금이나 분산 트랜잭션을 구현했다고 주장하지 않는다.

- 완료 디렉터리가 있으면 메타데이터의 접수번호·크기·해시와 ZIP을 검증한다. 일치하면 네트워크 호출 없이 skipped 결과를 반환하고 기존 fetched_at을 바꾸지 않는다.
- 결과가 불완전하거나 손상됐으면 명시적인 integrity 오류로 중단한다. 조용히 성공 처리하거나 원본을 자동 덮어쓰지 않는다. 자동 복구와 refresh는 후속 작업이다.
- 새 수집은 같은 파일시스템의 임시 디렉터리에 ZIP과 메타데이터를 완성한 뒤 최종 디렉터리로 이동한다. 중단된 임시 결과를 완료 결과로 인식하지 않는다. 파일 두 개 각각의 atomic replace만으로 묶음 전체가 원자적이라고 주장하지 않는다.
- 정상 예외 시 자신의 임시 결과를 정리한다. 강제 종료 잔여물의 자동 복구는 구현하지 않아도 되지만 README에 한계를 명시한다.
- 이번 skipped는 저장된 스냅샷 재사용을 뜻하며 원격 원본이 바뀌지 않았다는 보장이 아니다. 다른 접수번호의 정정공시는 별도 수집 대상이다.

Git에서 .env 및 로컬 비밀 설정, .venv/, data/, 임시 원본, 캐시를 제외한다. .env.example과 uv.lock은 추적한다. 테스트용 작은 ZIP/XML은 코드에서 합성하며 실제 공시 전체나 인증키를 커밋하지 않는다.

## 필요한 검증

구현 구조를 그대로 반복하는 테스트보다 아래 실제 실패를 검증한다.

1. 성공 ZIP은 받은 바이트 그대로 저장되고 해시·크기·접수번호가 일치한다.
2. 같은 입력의 두 번째 실행은 HTTP 호출 없이 재사용한다.
3. HTTP 200의 API 오류 XML을 성공으로 저장하지 않는다.
4. 손상 ZIP과 부분 저장 결과를 정상 완료로 인식하지 않는다.
5. 저장 도중 실패가 발생해도 불완전한 최종 결과가 공개되지 않는다.
6. 잘못된 접수번호/필요한 키 누락은 외부 요청 전에 실패한다.
7. timeout 등 HTTP 오류에 주입한 가짜 비밀키가 출력·로그에 나타나지 않는다.
8. 크기 제한 초과는 명시적으로 실패한다.

실 API 검증을 했다면 실제 접수번호, 성공 여부, 원본 크기, SHA-256을 작업 기록에 남긴다. 하지 못했다면 이유를 적는다. 오프라인 테스트 통과를 실제 DART 연결 확인으로 표현하지 않는다.
