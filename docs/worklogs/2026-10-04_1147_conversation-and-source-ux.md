# Conversation and source reading — 2026-10-04 11:47 KST

## Goal

공개 채팅을 한 번 질문하는 화면에서, 브라우저 안에 대화를 남겨 다시 열고 답변에 쓰인 공시 원문을 읽을 수 있는 상태로 닫는다. Retrieval과 Agent 의미는 바꾸지 않는다.

## Context

직전 화면은 FastAPI 정적 HTML이었다. 질문, SSE, citation, evidence drawer, 지원 기업 목록은 동작했다. 대화를 비우려면 새로고침이 필요했고, 화면 문구에 "근거"와 "색인"이 남아 있었다. 표로 파싱된 공시는 drawer에서 `사업부문 | 연결 회사명 | …`처럼 한 줄 문자열로만 보였다.

대화는 로그인 없이 이 브라우저에만 남긴다. 이전 질문을 다음 `/ask`에 넘기는 기능은 이번 범위가 아니다.

## Decisions

### 브라우저 저장소

문제: 답변과 공시 원문, 표 셀이 대화마다 쌓인다. `localStorage`는 보통 수 MB에서 막힌다.

후보: `localStorage`, IndexedDB.

선택: IndexedDB. 데이터베이스 `gongsimate`, object store `conversations`, key는 conversation id.

이유: 표 셀 텍스트가 retrieval 문자열과 함께 저장되면 대화 수가 늘 때 `localStorage` 한도를 넘기 쉽다. IndexedDB는 같은 브라우저에서 그 양을 감당한다.

저장 API는 UI 상태와 분리했다. `createConversationStore()`는 `list`, `get`, `save`, `delete`, `clear`만 제공한다. 화면은 이 인터페이스만 호출한다. 나중에 서버 저장으로 바꿀 때는 이 구현만 교체하면 된다. `clear`는 인터페이스에만 있고 화면 버튼은 두지 않았다.

### 저장과 문맥을 나눔

문제: 과거 화면을 다시 여는 일과, 모델이 이전 턴을 이해하는 일은 다르다.

선택: 저장은 브라우저의 대화 재생만 한다. `/ask` 요청에는 이번 질문만 보낸다. 이전 답변을 프롬프트에 붙이지 않는다.

이유: 멀티턴 문맥은 Agent 계약 변경이다. 이번 세션의 목표는 화면 복원이다. 빈 화면과 입력 힌트에는 "이전 답변은 다음 질문에 자동으로 이어지지 않습니다"를 그대로 둔다.

### 표 원문의 위치

문제: public evidence에는 검색용으로 평탄화한 `text`와, 셀 좌표가 빠진 locator만 있었다. 그 문자열을 `|`로 나누면 표가 아니어도 표처럼 보일 수 있다.

조사:

- 파서는 `element.table.cells`에 `start_row`, `start_col`, `rowspan`, `colspan`, `text`, `header_role`, `tag`를 둔다.
- Retrieval unit의 `source_refs`는 그 셀을 가리키지만 셀 문장은 없고 `text_sha256`만 있다.
- `SearchHit` locator는 `element_id`와 문자 구간만 남겨 셀 좌표가 빠진다.
- 이수페타시스 사업 표는 `th`가 아니라 `td`이고, 머리글 여부는 source ref의 `role`(`header` / `body`)에 있다.

선택: evidence를 만들 때 source ref와 파싱된 element를 맞춰 `blocks`를 붙인다. 검색 텍스트와 프롬프트 payload는 그대로 둔다. 파서, chunker, embedding, 색인은 다시 만들지 않는다.

표 블록은 같은 `element_id`의 셀 ref를 모으고, 파싱된 셀 문장과 `text_sha256`이 맞을 때만 넣는다. 해시가 다르면 그 셀은 버린다. 맞는 셀이 없으면 표 블록을 만들지 않는다. 좌표는 포함된 셀의 최소 행·열이 0이 되도록만 옮긴다. `rowspan` / `colspan`은 파싱된 값만 쓴다.

문단과 표가 한 evidence에 같이 있으면 ref 순서대로 `text` 블록과 `table` 블록을 나란히 둔다. 화면은 그 순서로 그린다. locator가 표를 가리키는데 표 블록이 없으면, 빈칸 대신 기존 검색 문장을 보여 내용이 사라지지 않게 한다.

### 화면 배치

왼쪽에는 제품명, 새 대화, 날짜별 대화 목록을 둔다. 지원 기업은 헤더 팝오버에 그대로 둔다. 채팅 열 너비는 유지한다.

제품명 `GongsiMate`는 홈 링크다. 클릭하면 문서를 다시 받지 않고 빈 대화를 연다. 저장된 대화는 지우지 않는다.

데스크톱 원문 패널 너비는 `min(800px, 62vw)`이다. 좁은 화면에서는 너비 100% 시트다. 대화 목록도 860px 이하에서는 헤더 아래에서 여는 시트다.

## Changes

- 홈 링크로 빈 대화를 연다. 진행 중인 응답은 끊고, 그때까지 받은 문장은 저장한다.
- 대화 제목은 첫 질문에서 끝의 물음과 "무엇인가", "설명해 주세요" 같은 꼬리를 덜어 만든다. 42자를 넘으면 말줄임이다. 제목용 모델 호출은 없다.
- 목록은 로컬 날짜 기준 오늘, 어제, 그 외 `YYYY.MM.DD`로 묶는다. 항목을 누르면 메시지와 citation을 다시 그린다. 삭제는 그 대화만 지운다.
- 저장 전에 citation 필드를 고른다. `source_sha256`, `retrieval_unit_id`, `corp_code`, 점수, 프롬프트, excerpt, 파일 경로는 넣지 않는다. `element_source_locator` 안의 해시도 뺀다.
- 사용자 문구를 바꿨다. "공시 근거 리서치"는 "공시 기반 리서치", 답변 배지 "공시 근거"는 "공시 원문 기반", "근거 N 열기"는 "원문 N 보기", drawer 본문 제목은 "공시 원문"이다. 범위 밖 안내에서 "색인"과 "DART에 없다"는 빼지 않은 채 "현재 지원하는 공시가 없습니다"로 맞췄다.
- 표는 `<table>`, `<thead>`, `<tbody>`, `<th>`, `<td>`로 그린다. 셀 문장은 텍스트로만 넣는다. 가로로 넘치면 패널 안에서 스크롤한다. 열 최소 너비를 두어 세 열 사업 표는 좁은 화면에서도 세 열이 보이게 하고, 더 많은 열은 스크롤되게 했다.
- 내부 status, evidence id, locator는 화면 코드와 "기술 정보"에만 남긴다. 기본 화면의 우선순위는 원문, 그다음 공시일·보고기간·섹션·접수번호다.

`/ask` 본문, retrieval 표현, planner prompt는 바꾸지 않았다.

## Failures / Findings

지원하지 않는 기업 질문의 배지와 제품 문구에서는 "색인"이 빠졌다. 다만 모델이 쓴 답변 문장에는 "현재 색인에서는 …"이 남아 있었다. 원인 후보는 planner와 시스템 프롬프트의 내부 표현이 답변으로 새어 나온 것이다. 그 프롬프트를 이번 세션에서 고치면 Agent 의미가 바뀌므로 두지 않았다.

모바일 대화 시트가 뷰포트 맨 위에서 열리면 `+ 새 대화`가 헤더에 가려졌다. 시트를 헤더 아래로 내려 버튼이 보이게 고쳤다.

## Retrieval / Product failures discovered

표 복원 경로는 이번 질문의 이수페타시스 사업 표에서 기대 열과 접수번호가 맞았다. Retrieval 순위나 누락 자체를 새로 측정하지는 않았다.

사용자에게 보이는 실패는 지원 범위 밖 답변의 "색인" 표현이다. 검색이 삼성SDI를 지원 기업으로 넣은 것은 아니고, 배지도 "지원 범위 밖"이었다. 문장만 내부 용어를 따라갔다.

## Remaining limitations

- 대화 주인은 브라우저다. 로그인, 계정, 서버 저장은 없다. 다른 브라우저나 저장소 삭제 뒤에는 대화가 없다.
- 저장해도 다음 질문은 이전 턴을 모른다. 멀티턴 문맥은 이후 별도 작업이다.
- 전체 삭제 버튼은 없다.
- 지원 범위 밖 답변의 모델 문장은 아직 "색인"을 말할 수 있다.
- 표가 아주 많은 열이면 좁은 화면에서는 가로 스크롤이 필요하다.
