# Public UI Product Pass — 2026-10-04 09:55 KST

## Goal

동작 중인 공시 리서치 채팅을, 포트폴리오에 공개 링크로 올려도 UI 때문에 신뢰를 잃지 않는 공개 베타 화면으로 한 단계 올린다. Retrieval, Agent, 색인 의미는 바꾸지 않는다.

## Context

직전 화면은 FastAPI 정적 HTML이었다. 질문, SSE, citation, evidence drawer, 지원 기업 목록은 동작했다. 다만 회사 다섯 곳이 왼쪽 열을 항상 차지하고, 빈 채팅은 비어 있었으며, 질문 예시에 동작 확인용 문장이 섞여 있었다. 답변 배지와 drawer 메타데이터가 검증 도구처럼 읽혔다.

검색 알고리즘, Dense 모델, filing 선택, planner prompt, TemporalScope, company resolution은 이번 세션의 변경 대상이 아니다.

## Decisions

### 화면 구조

문제: 지원 기업 목록이 첫 화면의 시각적 중심이었다.

후보: 사이드바 유지, 접는 패널, 헤더의 범위 팝오버.

선택: 채팅 열을 가운데에 두고, 지원 기업은 헤더의 `지원 기업 N곳`에서 연다.

이유: 회사 수가 늘어도 기본 레이아웃이 목록 길이에 묶이지 않는다. 범위는 숨기지 않되 첫 문장보다 앞에 두지 않는다. 목록은 `GET /api/corpus`만 읽는다.

### 프레임워크

새 UI 프레임워크는 넣지 않았다. 기존 `index.html`, `chat.css`, `chat.js`로 충분했다.

### 빈 화면과 입력

메시지가 없을 때는 한 문장 설명, 사용 힌트, 예시 질문을 보여 준다. 예시는 회사 이름을 소스에 적지 않고, corpus 회사 이름을 읽어 서로 다른 질문 틀에 넣는다. 법인 표기는 질문 문장에서만 덜어 낸다. 목록에는 API가 준 이름을 그대로 둔다.

첫 질문 전에는 설명과 입력창을 한덩어리로 두고, 질문이 생기면 입력창을 아래에 고정한다.

### 답변 상태

사용자에게 구분 가치가 있는 상태만 남긴다.

- 공시 근거
- 확인이 필요합니다
- 지원 범위 밖
- 해당 조건의 공시 없음
- 데이터 기준 이후의 시점
- 공시에서 확인하지 못함

직접 답변의 "바로 답변" 배지는 빼었다. 내부 status 문자열은 그리지 않는다.

본문과 공백을 접은 뒤 같거나, limitation이 본문에 그대로 들어 있으면 다시 보여 주지 않는다. 그 외 limitation은 접힌 "답변 범위"에 둔다. 문장 유사도 판정은 만들지 않았다.

### Evidence

Drawer는 회사, 보고서, 근거 본문, 그다음 공시일·보고기간·섹션·접수번호 순이다. 근거 ID와 문서 내 위치는 "세부 정보" 안에 둔다. `source_sha256`, `retrieval_unit_id`, `corp_code`, 파일 경로는 그리지 않는다.

근거 본문 맨 앞의 `[section]` 한 줄은 섹션 사실과 겹쳐서, drawer에서만 제거한다. 검색 텍스트 자체는 바꾸지 않는다. 섹션 경로의 연속 공백은 표시할 때 한 칸으로 줄인다.

Citation은 기존 `citation_id` / `evidence_id` 연결을 유지한다. 답변 문장을 정규식으로 추측해 citation을 만들지 않는다.

## Changes

- 제품 이름과 한 줄 설명을 헤더에 두었다. 첫 화면 문장은 "공시에서 근거를 찾아 기업을 조사합니다."
- 채팅을 최대 46rem 열로 두고, 지원 기업은 검색 가능한 팝오버로 옮겼다.
- 예시 질문, 입력창, 전송 상태, 로딩 문장, 답변, 확인, 범위 밖, 오류를 다시 배치했다.
- Evidence drawer 정보 순서를 본문 우선으로 바꿨다.
- 정적 UI 계약 테스트에 제품 문구, 범위 버튼, 숨겨야 할 내부 필드, 회사명 하드코딩 금지를 보탰다. "대상"도 소스에 없어야 한다.

Backend 검색·에이전트 의미는 변경하지 않았다. `/api/corpus` 응답 형식도 그대로다.

## Failures / Findings

같은 질문 "이수페타시스의 주요 사업은 무엇인가?"를 두 번 보냈을 때 답변 문장과 citation 수가 달랐다. 첫 실행은 citation 1개, 둘째는 2개였다. 둘 다 같은 반기보고서였다.

Drawer 근거 본문은 표가 파이프 문자로 이어진 구간이 있어 좁은 화면에서 줄바꿈이 많다. 원문 표현이라 이번 세션에서 재구성하지 않았다.

## Retrieval / Product failures discovered

고치지 않았다. 다음 Retrieval Quality 작업의 입력이다.

- "주요 사업" 질문이 사업보고서가 아니라 반기보고서 (2026.06), 접수번호 20260814002283을 근거로 삼았다. 섹션은 `II. 사업의 내용 · 1. 사업의 개요`와 `I. 회사의 개요 · 1. 회사의 개요`였다.
- 같은 질문의 두 실행에서 citation 수와 문장이 달랐다. 근거 문서는 둘 다 위 반기보고서였다.
- 섹션 이름에 "목 차"처럼 공백이 끊긴 표기가 있다. 화면에서는 연속 공백만 줄였다.
- 근거 텍스트 앞에 `[section]` 위치 줄이 포함된다. Drawer 표시에서 맨 앞 한 줄만 숨겼다. chunk 텍스트는 그대로다.
- 삼성전자 실적, 대상 사업 구조 예시는 이번 세션에서 성공 응답까지 확인하지 않았다. 삼성전자 질문은 연결 오류 확인에 썼다.

## Remaining limitations

- 지원 기업은 아직 다섯 곳이다. 범위는 팝오버로 보이지만 커버리지 자체가 넓어진 것은 아니다.
- 이전 답변은 다음 질문에 이어지지 않는다.
- 로그인, 대화 저장, 비교, 차트, 내보내기는 없다.
- 기술적 위치 정보는 접혀 있을 뿐 응답에서 제거된 것은 아니다.
- 모바일은 읽고 질문하고 근거를 열 수 있는 수준이다. 모바일 전용 제품으로 다듬지는 않았다.
