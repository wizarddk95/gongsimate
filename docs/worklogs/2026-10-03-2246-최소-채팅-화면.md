# 2026-10-03 22:46 — 기존 런타임 위의 최소 채팅 화면

검색 품질 평가보다 먼저, 이미 동작하는 product Runtime을 한 화면에서 질문하고 근거를 열어볼 수 있게 했다. 디자인 시스템이나 공개 서비스가 아니다.

## 붙인 방식

저장소에 프론트엔드 프레임워크는 없었다. API는 FastAPI `disclosure_agent.agent.api`이고, `POST /ask`가 SSE(`text/event-stream`)다. 새 웹 프레임워크는 넣지 않았다. 같은 프로세스가 정적 화면을 제공한다.

```
브라우저
  GET /                  index.html
  GET /static/chat.js
  GET /static/chat.css
  GET /api/corpus        회사명, corpus_as_of, filing_count
  POST /ask              기존 SSE
        → AgentRuntime
        → answer_directly | search_disclosures | ask_clarification
        → 근거 있는 답과 citation 이벤트
```

같은 출처라 CORS 설정은 없다.

## 화면

한 채팅 화면이다. 질문, 전송, 사용자 메시지, 답변, 실행 중, 오류를 구분한다.

- 검색 없이 답하면 직접 답변으로 보여 주고 인용 단추를 만들지 않는다.
- 되물으면 질문과 후보 회사 단추를 보여 준다. 후보를 누르면 `clarification`과 함께 다시 `POST /ask`를 보낸다.
- 공시 검색 답은 본문과 인용 단추로 보여 준다.
- 스트리밍은 `fetch`로 SSE를 읽는다. `answer.delta`는 본문에 이어 붙이고, `citation` 이벤트는 `citation_id`로 보관한다.
- 네트워크 오류와 `error` 이벤트는 답변을 지우지 않고 오류 상태로 남긴다.

지원 범위는 `GET /api/corpus`만 읽는다. 회사 이름과 날짜를 화면에 적지 않는다. 회사마다 `corpus_as_of`가 다르므로 하나의 기준일을 만들지 않는다. 목록에 없는 기업은 검색하지 않는다는 설명을 같이 보여 준다.

## 인용

인용 번호는 답변 문장을 정규식으로 추측하지 않는다. 런타임이 주는 `citation_id`와 `evidence_id`만 단추로 만든다. 본문에 이미 `[n]`이 있으면 그 번호가 citation 맵에 있을 때만 단추로 바꾸고, 없으면 완료 시점의 `answer.citations`로 단추를 붙인다.

서랍은 공개 필드만 연다. 회사명, 문서·보고서명, 접수번호, 접수일, 보고기간, 섹션 경로, 근거 텍스트, element locator, citation id. 페이지 번호는 없다. 파서는 `PGBRK`를 페이지로 세지 않는다. 근거 전문은 `Evidence.to_dict`의 `text`다. 기존 `excerpt`는 480자다.

## 공개 경계

`/api/corpus`와 화면은 파일 경로, `index_dir`, `corp_code`, 스택, 프롬프트, 원본 observation을 보내지 않거나 그리지 않는다. `POST /ask` 완료 이벤트의 evidence에는 기존처럼 `source_sha256`, `retrieval_unit_id`, `corp_code`가 남아 있다. 화면은 그리지 않는다. 이번 커밋에서 그 필드를 응답에서 빼지는 않았다.

## 평가 라벨

`why-that-year`(「이수페타시스 그해 매출이 좋아진 이유」)는 독립 턴에서 「그해」의 대상이 없다. 기대 행동을 `ask_clarification`으로 바꿨다. 최신 실적 검색 케이스는 `latest-*`에 그대로 둔다. 플래너 프롬프트는 바꾸지 않았다. 기대가 `ask_clarification`인데 다른 행동이면 grader 오류는 `clarification_missing`이다.

`evaluation/tool_planning/latest_run.json`은 2026-10-03 18:54 재실행본이 작업 트리에 있었다. 그 기록의 `why-that-year`는 아직 `category: explanation`, `pass: false`, `required_search_omitted`다. 고친 라벨과 맞지 않아 이 커밋에 넣지 않았다. 48/49를 갱신한 것으로 읽으면 안 된다.
