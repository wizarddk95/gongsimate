# TASK-003C 파서 잔여 결함 — 변경 계획

이전 리뷰 2번(병합 범위 제한)과 3번(셀 안 여러 중첩 표 연결)은 유지한다. 재설계하지 않는다.

## A. locator 컨텍스트

`_PATHS` 전역 dict를 없앤다. 경로 맵은 멤버 트리마다 `_TreeContext`(원본 SHA, 멤버 순번, 멤버 이름)에 둔다. 스레드 로컬로 우회하지 않는다.

`parse_receipt`, `resolve_locator`, `element_text_at` 서명은 유지한다. locator는 호출 사이에 남은 전역 맵을 읽지 않는다. `resolve_locator`는 넘긴 멤버 텍스트로 트리를 새로 만들고 `path`만 따라간다. 같은 파일명의 멤버는 `member_index`로 구분한다.

## B. 미지원 래퍼의 제목

알려진 컨테이너와 같은 방식으로, 래퍼 안에서만 뒤 형제에 제목 경로를 잇는다. 리스트를 제자리에서 늘리지 않아 래퍼 밖·다음 문서로 새지 않게 한다. `<CORRECTION>`은 계속 미지원이며 `partial`을 유지한다.

## C. 파서 산출물 잠금

수집 `.sync.lock`은 쓰지 않는다. 결과 디렉터리(설정 해시 앞 16자 경로)에 `os.O_EXCL` 파일 잠금을 둔다. 검증·격리·재사용·공개를 잠금 안에서 한다. 대기 후 완료본이 있으면 재사용한다. 시간 초과는 `ParseLockTimeout`(종료 코드 3)이며 원본 손상이나 파싱 실패로 기록하지 않는다. 임시 디렉터리는 `pid`+uuid이고, 실패 시 그 경로만 지운다. 다른 실행의 `.tmp-*`·lock·완료본은 지우지 않는다. 강제 종료 잔여물의 자동 삭제는 하지 않는다.

잠금은 로컬 NTFS에서만 검증한다. 분산 잠금이 아니다.

## D. CLI

종료 코드 0/1/2는 유지한다. 앞에 `status`와 `search_eligible`을 두고, `partial`이면 처리 완료·검색 입력 제외를 적는다. 버전·해시·재사용·manifest 경로·멤버 상태·경고 코드를 보인다. 경고가 길면 개수, 생략, manifest 경로를 적는다. 검색 자격의 기준은 manifest다.

## E. 단위

셀·문단 원문은 그대로 둔다. 관측된 괄호 단위 라벨만 `unit_mentions`로 남기고 `applies_to`는 비운다. 표 안이라는 이유나 앞 문단과의 인접만으로 적용 범위를 확정하지 않는다. 혼합 표기 `(단위: 백만원, %)`는 하나의 배수로 만들지 않고 `unresolved`로 둔다. 라벨이 없으면 키를 두지 않아 부재와 구분한다. 청커는 구현하지 않고, 청킹 시 이 근거를 문맥으로 실어야 한다는 계약만 문서화한다.

파서 버전 `2`, 스키마 `2`. 전처리 버전은 `2`를 유지한다. 설정에 단위 방침을 넣어 해시가 바뀌고, 이전 `p1/` 결과는 덮어쓰지 않는다.

## 구현 후 확인

설정 해시는 `2d75d2abcee582315a440b126806f22760c813a3f14cf4b16d563b517dc7f0e7`(경로 키 `2d75d2abcee58231`)이다. 출력은 `p2/2d75d2abcee58231/`이다. `p1/db9fcf69916c6280/`은 그대로다.

저장소의 이수페타시스 ZIP 12건을 새 버전으로 다시 처리했다. 원본 ZIP은 수정하지 않았다. `success` 11건은 요소 수·텍스트·`section_path`가 p1과 같다. `element_id`는 파서 버전과 locator 필드가 바뀌어 전부 다르다. 이것은 내용 손실이 아니다.

정정본 `20250321001007`만 `section_path`가 22곳 달라졌다. 세 멤버 모두에서, 비어 있던 경로가 `['정 정 신 고 (보고)']`가 된 경우뿐이다. 그 제목이 래퍼 밖(대표이사 확인 등)으로 붙지 않았다. 패키지는 `partial`, `search_eligible`은 false다. 검색 가능하다고 보지 않는다.

재사용 무결성 검사는 `COMPLETE`와 필수 파일의 읽기, manifest·전처리 보고서 JSON, 스키마·원본 SHA·파서·전처리 버전·전체 설정 해시, 비어 있지 않은 preview, `elements.jsonl` 각 줄의 JSON과 줄 수=`element_count`까지다. 내용 해시는 없다. 줄 수를 유지한 JSON 변조는 검출하지 않는다.

잠금은 이 Windows NTFS 로컬 디스크에서 프로세스 두 개로 확인했다. 다른 OS는 확인하지 않았다.

## 남은 한계

- `<CORRECTION>`은 미지원이다. 제목 경로만 고쳤고 `partial`을 유지한다.
- 단위 라벨의 적용 범위는 확정하지 않는다. `conflict`는 범위를 정하려다 충돌한 상태가 아니므로 이번 출력에 없다. 서로 다른 라벨은 `unresolved`다.
- 강제 종료 뒤의 `.tmp-*`와 lock은 자동으로 지우지 않는다.
- 재사용 검사는 동일 줄 수의 내용 변조를 보지 못한다.
- 청커·검색·평가셋 정답은 만들지 않았다. 평가에 쓸 `element_id`는 p2 결과를 기준으로 새로 고정해야 한다.
