# TASK-003C worklog — 이수페타시스 정기공시 10건 파싱 검증

대상은 이수페타시스(007660, corp_code 00107613)의 저장된 정기공시 10건이다. DART API는 호출하지 않았고, 원본 ZIP은 수정하지 않았다. 입력은 `--source-sha256`으로 고정했다. 20260515002006, 20260814002283은 이번 10건이 아니다.

현재 파서 설정 해시는 `db9fcf69916c628090f96bd4dcb4abf00104e03d3864922758c90ded108198cc`(경로 키 `db9fcf69916c6280`), 전처리 버전 `2`, 파서 버전 `1`이다. 위치는 ZIP 바이트 오프셋이 아니라 디코딩된 멤버 텍스트의 유니코드 코드포인트 오프셋이다.

## 발견한 결함

전처리 버전 1에서는 이름처럼 보이는 꺾쇠를 확정 리터럴이 아니면 `uncertain_named_angle`로 `partial`에 두었다. 원문을 읽어 아래 토큰은 속성과 닫는 태그가 없는 문단·셀 텍스트였다.

이 토큰만 허용 목록에 넣고 전처리 버전을 `2`로 올렸다. 설정 해시가 바뀌어 `p1/60297c5eee494cb6/`와 `p1/ba0022781fbb025d/`는 덮어쓰지 않았다. 10건 ZIP SHA-256은 파싱 뒤에도 지정 해시와 같다.

`<CORRECTION>…</CORRECTION>`은 제목과 표를 감싸는 구조 태그다. 허용 목록에 넣지 않았고 `partial`로 두었다.

## 이미 충족한 항목

- 제목·문단·표가 남고, 표 안 문단 `(1) 당기말 및 전기말 현재 지분법적용투자주식의 내역은 다음과 같습니다.`는 셀 텍스트와 자식 표로만 있고 본문 문단 중복은 0건이다. 원문은 `20260323000847.xml` 코드포인트 1020451 근처의 `TD` 안 `P`와 중첩 `TABLE`이다.
- 병합 값 비복제: 같은 멤버 표지와 `20250320001435.xml` 코드포인트 1100의 `ROWSPAN="2"` 셀 `사업연도`는 셀 1개다. 두 번째 행에 그 값이 반복되지 않는다.
- 빈 표 유지: `20260323000847.xml` 코드포인트 463568의 `TABLE`은 빈 `TD` 하나이고 자식 `TABLE`·텍스트·`IMAGE`가 없다. 파서도 셀이 모두 빈 표를 838개 남겼다.
- 인라인·공백·부호·괄호·단위: `20260323000847.xml` 코드포인트 11456의 `SPAN` 연속은 한 문단으로 이어지고 `법적ㆍ상업적`, `(주)이수페타시스`, 내부 이중 공백이 남았다. `20240514001613.xml` 코드포인트 8754의 셀은 `(단위 : 백만원, %)`, 코드포인트 1769 근처 셀은 `2024년     5월    14일`이다. `20240814003325.xml` 코드포인트 5415은 `(단위 : 사)`다. 셀 가장자리 공백만 잘리므로 `> 부터</TD>`의 앞 공백은 `부터`가 된다.
- 허용 목록 리터럴 `<신설>`(83212), `<연결기준_2025년>`(91720), `<연결기준_2024년>`(77829)과, 목록에 없던 이름형 꺾쇠는 위 표와 `<주식매수선택권의 부여 및 행사현황>`(공백이 있어 태그 이름이 아님)이 출력에 남았다.
- 이미지 `대표이사등의확인.jpg`와 캡션은 요소로 남고 OCR은 없다.
- 정정본 제목 `정 정 신 고 (보고)`는 `20250321001007.xml` 코드포인트 734에서 읽어 요소로 남았다. 패키지는 `partial`이다.
- 원본 불변, 설정 해시가 다르면 결과 공존.

## 남은 한계

- `<CORRECTION>`은 미지원 구조다. 20250321001007은 검색에 넣지 않는다.
- 이 10건은 모두 이수페타시스다. 다른 기업으로 일반화하지 않는다.
- 요소 개수는 완전성이 아니다. 표본은 사업보고서·분기·반기·원보고서·정정본에 걸친 작은 구간이다.
- locator 왕복은 전처리 뒤 같은 트리의 자식 순번 검사다. 이번 대조와 별개다.

## 변경 이유와 아직 주장하면 안 되는 범위

확인된 리터럴이 `partial`이 되지 않게 허용 목록과 전처리 버전만 올렸다. `<CORRECTION>`을 성공으로 바꾸지 않았다. 이 결과로 다른 기업의 꺾쇠, HTML, 계정 의미, 정정 diff, 검색 품질을 보장하지 않는다.
