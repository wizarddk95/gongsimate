# TASK-003B worklog — 전처리 안전성과 결과 재사용

## 발견한 결함

- 알려진 ASCII 태그가 아니면 `<`를 텍스트로 이스케이프한 뒤 엄격 파싱이 성공했다. `<NOTE>본문</NOTE>`처럼 지원하지 않는 태그의 텍스트는 `P` 밖이면 요소로 남지 않았다.
- 재사용은 `COMPLETE`, 원본 SHA, 파서 버전, 전체 `config_hash`, 요소 줄 수만 보았다. `preview.md`와 스키마, 각 줄의 JSON, 전처리 버전은 확인하지 않았다. 전체 해시가 다르면 재사용하지 않고 같은 16자 경로를 덮어쓸 수 있었다.
- 재사용 반환값에 경고가 없어, 호출자는 디스크의 `partial`과 달리 경고를 잃을 수 있었다.

## 이미 충족했던 항목

- DOCTYPE/`ENTITY` 거부는 멤버를 `failed`로 둔다.
- ZIP 경로 이탈은 `..`와 절대 경로를 거부한다. 비정상 팽창은 수집 검증의 압축 해제 합 상한과 파서의 멤버 30MiB 상한이 이미 막는다.
- `COMPLETE`는 임시 디렉터리에 파일을 쓴 뒤 이름을 바꿀 때만 생긴다. 중단 시 완료로 보이지 않는다.
- 확인된 리터럴 보정은 이전에도 멤버를 자동으로 `partial`로 만들지 않았다. 이번에도 그 기준을 유지한다.
- 기존 locator 대조는 전처리 이후 같은 ElementTree에서 `{tag, index}`를 다시 찾는 왕복이다. 원본 바이트 오프셋 검증이 아니다. 이 왕복 테스트는 남겨 두었다.

## 바꾼 동작

- 전처리 버전 `1`을 설정에 넣어 `config_hash`가 달라진다. 이전 `p1/<구 해시 16자>/` 결과는 덮어쓰지 않는다. 원본 ZIP도 수정하지 않는다.
- 안전 보정: 허용 목록 `<신설>`, `연결기준_`, `별도기준_`, 태그 이름이 아닌 `<`, 이미 있는 엔티티가 아닌 `&`. 위치는 디코딩된 멤버 텍스트의 유니코드 코드포인트 오프셋이다.
- 모르는 ASCII 태그는 텍스트로 바꾸지 않고 트리에 남긴다. 직속 텍스트를 요소로 남기고 `partial`이 된다.
- 허용 목록에 없는 이름형 `<...>`는 이스케이프하되 `uncertain_xml_structure`로 `partial`이다.
- 보정 전후는 `preprocess_report.json`에 둔다. 안전한 보정만으로 `partial`이 되지 않는다.
- 재사용 전에 필수 파일, 스키마, 원본 SHA, 파서·전처리 버전, 전체 설정 해시, 요소 JSON을 확인한다. 손상 결과는 `quarantine/`으로 옮긴 뒤 다시 만든다. 전체 해시가 다르면 재사용하지도 덮어쓰지도 않는다.
- 완료된 `partial` 재사용은 상태와 경고를 유지한다. `search_eligible`은 `overall_status == success`일 때만 참이다. 검색 코드는 아직 없고, 이 계약만 문서화했다.

## 남은 한계

- 허용 목록은 이번 이수페타시스 세 ZIP에서 본 리터럴이다. 다른 기업의 다른 꺾쇠는 `partial`이거나 실패할 수 있다.
- 독립 대조는 그 세 건의 일부 구간이다. 테스트 통과, locator 왕복, 이 대조, 다른 기업에 대한 품질은 서로 다른 주장이다.
- 2026 분기·반기 보고서는 형식 확인이다. 제품 대상 사업연도 2023~2025를 바꾸지 않는다.
- 빈 표 대표 1건(`20260323000847.xml` 코드포인트 463568)은 빈 `TD`만 있고 자식 표·이미지·텍스트가 없었다. 빈 표를 삭제하지 않았다. 모든 빈 표를 분류하지는 않았다.
- 검색 파이프라인은 없다. `partial`을 영향 없는 요소만 받는 정책은 아직 없다.
